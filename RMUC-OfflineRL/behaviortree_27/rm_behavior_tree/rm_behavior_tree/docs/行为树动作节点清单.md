## 二、订阅类动作节点（`BT::RosTopicSubNode<T>`）

统一行为：基类按 `topic_name` 端口创建订阅，每个 tick 把“自上次 tick 以来的最新消息”交给 `onTick`；有新消息才写输出端口，**无消息也返回 SUCCESS**（不因没数据而失败）。

| XML 标签 | C++ 类 | 消息类型 | 端口 | 源码 |
| --- | --- | --- | --- | --- |
| `SubGameStatus` | `SubGameStatusAction` | `robot_msgs/GameStatus` | in `topic_name` / out `game_status` | `plugins/action/sub_game_status.cpp` |
| `SubRobotStatus` | `SubRobotStatusAction` | `robot_msgs/RobotStatus` | in `topic_name` / out `robot_status` | `plugins/action/sub_robot_status.cpp` |
| `SubAllRobotHP` | `SubAllRobotHPAction` | `robot_msgs/AllRobotHP` | in `topic_name` / out `robot_hp` | `plugins/action/sub_all_robot_hp.cpp` |
| `SubAutoAimStatus` | `SubAutoAimStatusAction` | `robot_msgs/AutoAimStatus` | in `topic_name` / out `auto_aim_status` | `plugins/action/sub_auto_aim_status.cpp` |
| `SubChassisEnergy` | `SubChassisEnergyAction` | `robot_msgs/ChassisEnergy` | in `topic_name` / out `chassis_energy` | `plugins/action/sub_chassis_energy.cpp` |
| `SubRuneStatus` | `SubRuneStatusAction` | `robot_msgs/RuneStatus` | in `topic_name` / out `rune_status` | `plugins/action/sub_rune_status.cpp` |
| `SubRemoteStatus` | `SubRemoteStatusAction` | `robot_msgs/RemoteStatus` | in `topic_name` / out `remote_status` | `plugins/action/sub_remote_status.cpp` |
| `SubDecisionNum` | `SubDecisionNumAction` | `rm_decision_interfaces/DecisionNum` | in `topic_name` / out `decision_num` | `plugins/action/sub_decision_num.cpp` |
| `SubArmors` ⚠️未启用 | `SubArmorsAction` | `auto_aim_interfaces/Armors` | in `topic_name` / out `armors` | `plugins/action/sub_armors.cpp` |

说明：
- `topic_name` 在 XML 中给静态话题名（如 `/game_status`）；这些节点由 `params_update_msg`（节点名 `update_msg`）承载，但 **`BT::RosTopicSubNode<T>` 基类自带 callback group 与自己的 executor，在 `tick()` 里 `spin_some()`（`bt_topic_sub_node.hpp:302`），所以并不依赖主程序的 `executor.add_node` 名单**。
- 真正**必须**把节点加进主 executor 的是"裸订阅"节点——它们直接用 `nh->create_subscription()`，回调落在节点默认 callback group 上：`SubTargetPos`、`SubGimbalTarget`、`MoveAround` 的 `/map`、`GetCurrentLocation` 的 TF 监听器。这也是 `rm_behavior_tree.cpp` 注释里强调 `update_msg` 必须在 executor 名单中的原因。
- `SubArmors` 的 `ament_auto_add_library(sub_armors …)` 在 `CMakeLists.txt` 中已注释，`rm_behavior_tree.cpp` 的 `msg_update_plugin_libs` 中也被注释，因此**当前不会被加载**；主树改用 `SubTargetPos` 获取装甲板数据。

注意：
- `PubAutoAimMode::setMessage` 先读 `auto_aim_mode`、读不到才回退 `key_name`。**但 `key_name` 实际是死代码**：
  因为 `auto_aim_mode` 声明了默认值 `0`，`getInput<int>("auto_aim_mode")` 永远成功，回退分支永不执行。

## 五、导航 / 运动 / 状态查询类动作节点

### `SendGoal`
- 类：`SendGoalAction : BT::RosActionNode<nav2_msgs::action::NavigateToPose>`（`plugins/action/send_goal.cpp`）
- 作用：把目标点发给 Nav2 的 `navigate_to_pose` 动作服务器并跟踪执行结果。本工程唯一“真正把机器人开过去”的节点，`MoveAround` / `PursueEnemy` 只负责算点。
- 行为细节：
  - `setGoal` 解析 `"x; y; z; qx; qy; qz; qw"`（分号或空格分隔，格式非法直接抛异常），`frame_id` 固定 `map`，时间戳用 `node_->now()`（跟随 `use_sim_time`，避免仿真里 TF 外推失败）；
  - `onFeedback` 里若发现 `goal_pose` 端口值变了 → `halt()` 并返回 FAILURE（让上层换新目标重发）；
  - 到达判定不看 Nav2 的 result，而是**连续 5 次反馈 `distance_remaining < 0.2`** → 取消当前目标并返回 SUCCESS；
  - `ABORTED` / `CANCELED` / 结果码未知 / 服务端拒绝 / 发目标超时 → FAILURE；基础类另有“超过 10 × server_timeout 无反馈”的兜底 FAILURE。
- 端口：`goal_pose`(string，格式 `"x; y; z; qx; qy; qz; qw"`，map 系)、`action_name`(string，基础端口，默认占位符)。
- ⚠️ 隐患：`params_send_goal.default_port_value = "goal_pose"`，若 XML 省略 `action_name`，会退化成用 `"goal_pose"` 当动作服务名。现有 XML 都显式写了 `action_name="navigate_to_pose"`，建议保持。

### `MoveAround`
- 类：`MoveAroundAction : BT::SyncActionNode`（`plugins/action/move_around.cpp`，另链接 `src/map_accessor.cpp`、`src/key_point_loader.cpp`、`src/visibility_checker.cpp`）
- 作用：以当前位姿为圆心、`expected_dis` 为半径在圆周上随机取点，做三级校验（1. 在栅格图范围内；2. 占用值 ≤50 且非未知区域，除非 `allow_unknown`；3. 从当前位置到落点直线可达），最多重抽 `max_resample` 次；成功则把目标写成字符串输出给 `SendGoal`。**SUCCESS 只代表“撒出了一个合法点”，不代表走到了。**
- 说明：地图订阅在**构造函数**里建立（`/map` 用 `transient_local + reliable` QoS 以兼容 latched 地图），`node_` 复用被 spin 的 `update_msg` 节点；缺 `message`、还没收到地图、或抽不到合法点都返回 FAILURE。
- ⚠️ `map_topic`、`expected_dis`、`goal_clearance`、`max_resample`、`allow_unknown` 是**在构造函数中读取**的，运行期再改这些端口（尤其是写成黑板指针 `{...}`）不会生效，会退回工厂默认值。
- 端口：

| 端口 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `message` | `geometry_msgs/TransformStamped` | — | 机器人当前位置（来自 `GetCurrentLocation`），每 tick 读取 |
| `expected_dis` | double | 0.3 | 撒点半径 / m |
| `map_topic` | string | `/map` | 栅格地图话题 |
| `goal_clearance` | double | 0.0 | 直线可达检查安全间隔 / m，0=只查栅格本身 |
| `max_resample` | int | 20 | 单次 tick 最多重抽次数（<1 时强制为 1） |
| `allow_unknown` | bool | false | 是否允许落在未知区域（-1） |
| `goal_pose` | string | — | 输出目标 `"x;y;z;0;0;0;1"`（固定 4 位小数、单位四元数），交给 `SendGoal` |

### `PursueGoal`（MoveAround 模式的新版追击节点，2026-10 新增）

- 类：`PursueGoalAction : BT::SyncActionNode`（`plugins/action/pursue_goal.cpp`，另链接 `map_accessor` / `key_point_loader` / `visibility_checker`）
- 作用：**只算追击点**，写成 `"x;y;z;qx;qy;qz;qw"` 输出到 `goal_pose`，执行交给 `SendGoal`。老 `PursueEnemy` 保留可用。
- 与老节点的差别：不持有 action client / goal_handle（因此没有"自建节点没进 executor → 回调不执行、取消失效"的问题），状态可预测，和 `MoveAround + SendGoal` 行为统一。
- 算法：选最近装甲板 → 3 帧滑窗均值滤波 → 在「敌人→自身」连线上取距敌人 `pursue_radius` 的点（z 用自身高度、朝向敌人）→ 可选贴墙检查（`/map` 用 `transient_local + reliable` 订阅）。
- 防抖：只有追击点移动超过 `min_goal_change` 才改写输出，并用 `update_interval` 限速 → `SendGoal` 不会因为抖动反复取消/重发。
- 返回：有可用追击点 → SUCCESS；无敌人 / 缺位姿 / 被墙挡 → FAILURE。
- ⚠ 必须放在 `ReactiveSequence` 里（普通 `Sequence` 会让它只算一次就不再看敌人）。
- 实测（robot(2,2)、radius 2.5）：敌(5,2) → `2.5000;2.0000;…;1.0000;0.0000`；敌(2,5) → `2.0000;2.5000;…;-0.7071;0.7071`；敌人 0.1 m 小移动不重发、1.0 m 大移动才从 `2.5000` 改到 `3.5000`。

### `PursueEnemy`
- 类：`PursueEnemyAction : BT::StatefulActionNode`（`plugins/action/pursue_enemy.cpp`，同样链接地图/可视性工具源码）
- 作用：追击最近的敌人。`onStart` 发初始追击点并返回 RUNNING；`onRunning` 按 `update_interval` 节奏复查敌人，用滑动窗口（`kEnemyHistorySize`）取均值滤波抑制装甲板自旋抖动，只在需要时取消旧目标并重发新追击点。
- 实际返回语义（与头文件注释不完全一致）：

| 情况 | 返回 |
| --- | --- |
| `armors` 为空、缺失 `current_location`、`armors[0]` 位置为 (0,0,0)、或启用 `wall_check_clearance` 时机器人与敌人之间被墙挡住 | FAILURE（并取消当前导航目标） |
| 正常追击中 | RUNNING |
| 累计发点次数达到 `max_pursuit_points` | SUCCESS（取消当前目标后退出） |

- ⚠️ 两处与注释/端口不符的实现细节：
  1. `enemy_timeout` 端口在 `onStart` 被读取后，紧接第 105 行又被硬编码覆盖为 `10.0`，**端口值实际无效**（判定始终按 10 s）。
  2. 成员 `arrived_at_enemy_`、`navigation_complete_` 由 action 结果回调赋值，但 `onRunning` 从未使用，**“到达后停下自瞄”的 SUCCESS 分支并未实现**；唯一能返回 SUCCESS 的路径是发点次数用尽。
- ⚠️ `pursue_enemy` 这个 rclcpp 节点（`rm_behavior_tree.cpp` 里的 `params_pursue_enemy.nh`）**没有加入主程序的 executor**（只 spin 了 `node`、`update_msg`、`get_current_location`、`send_goal`、`pub_default`），因此它自带的 `/map` 订阅与 action 结果回调不会被处理：`wall_check_clearance > 0` 时会因“还没收到地图”而放行，`goal_handle_` 也不会被赋值（`async_cancel_goal` 无效）。需要这几项能力时，应把该节点一并加入 executor。
- 端口：

| 端口 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `armors` | `auto_aim_interfaces/Armors` | — | 敌人装甲板（来自 `SubTargetPos`） |
| `current_location` | `geometry_msgs/TransformStamped` | — | 自身位置（来自 `GetCurrentLocation`） |
| `pursue_radius` | double | 2.0 | 保持交战距离 / m |
| `pursue_distance_threshold` | double | 0.5 | 敌人移动超该距离才重发目标 / m |
| `max_pursuit_points` | int | 10 | 最多发送追击点数量 |
| `update_interval` | double | 0.5 | 更新间隔 / s，0=每 tick 更新 |
| `enemy_timeout` | double | 3.0 | 敌人数据超时 / s |
| `action_name` | string | `navigate_to_pose` | 导航动作服务器名 |
| `target_frame` | string | `map` | 导航目标坐标系 |
| `robot_base_frame` | string | `gimbal_yaw` | 机器人基坐标系 |
| `map_topic` | string | `/map` | 障碍检查地图话题 |
| `wall_check_clearance` | double | 0.0 | 贴墙检查最小间隙 / m，0=关闭 |

## 十、编写新的动作节点时的检查清单

1. 头文件放 `include/rm_behavior_tree/plugins/action/`，实现放 `plugins/action/`，命名空间 `rm_behavior_tree`。
2. 静态 `providedPorts()`：ROS 话题节点务必 `return providedBasicPorts({...})`（否则丢 `topic_name`，参见 `RobotControl`）；动作节点用 `providedBasicPorts({...})` 以保留 `action_name`。
3. 新节点需要 ROS 通信时用 `CreateRosNodePlugin(类, "XML标签")`，纯逻辑用 `BT_REGISTER_NODES`。
4. 在 `CMakeLists.txt` 增加 `ament_auto_add_library(<插件库名> SHARED …)` + `add_target_dependencies(...)`。
5. 在 `src/rm_behavior_tree.cpp` 注册：需要 ROS 参数的加进 `RegisterRosNode` 列表，纯逻辑不加进 `bt_plugin_libs`。
6. 在 XML 的 `<TreeNodesModel>` 里补 `<Action ID="XML标签">` 与端口声明，Groot2 面板才会显示。
