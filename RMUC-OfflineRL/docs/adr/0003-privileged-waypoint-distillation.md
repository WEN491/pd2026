# ADR-0003 用人类步兵当老师，在特权信息下蒸馏航点

- 状态：已接受
- 日期：2026-02（章程落笔时）

## 背景

雷达**没有任何动作日志**。数据集的 `timeseries` 只覆盖 8 类实体（英雄/工程/步兵3/步兵4/空中/哨兵/基地/前哨站），雷达不在其中；规则手册为雷达保留了编号 9，但数据里没有它的行。雷达可观测的痕迹只有两处**结果**：

1. `是否易伤`——被对方雷达标记高亮，是进度的**结果位**，不是动作
2. `雷达反制UAV` 事件

因此不存在可模仿的雷达行为。同时有一个数据事实约束了标签选择：

- 哨兵单场仅覆盖约 25.4 / 420 格，位置熵 1.76 nats，81% 的时间集中在 5 个格子内
- 步兵单场覆盖约 73 格，位置熵 3.49 nats

## 决策

以**人类步兵的导航行为**作为主要监督标签，哨兵数据用于**校验与可达性检查**。

训练时同时提供两种观测：雷达的全场视角，与哨兵机载的可见集。目标是学会**依赖信息差的那部分决策**——即"因为看得到更多，所以该去哪"。

## 理由

1. **哨兵数据没有可学的方差**。本架构的全部价值在于"根据全场战况决定去哪"，而哨兵轨迹恰恰缺少这种方差；单用哨兵数据，最好的结果是复现各队固定岗位，最坏的结果是把不同队伍的岗位平均成一个不存在的点。
2. **步兵与哨兵构造等价**（同为 400 血 / 260 热 / 17mm，发弹量相当），这一等价性已由仓库的前期分析确立，是迁移成立的前提。
3. **特权信息正是本架构的立足点**。雷达能看到哨兵看不到的敌人，把这一点作为训练时的输入差异，直接对应仓库承认但从未实施的那条待办（"部署时把机器人真正能感知的东西喂进同样的槽位"）。

## 后果

- 观测层需要**双输入**：全场视角 + 机载可见集。部署时两者都有（雷达确实全场；哨兵侧收到的就是雷达下发的航点），但训练时必须显式区分，否则会学成"模仿一个信息更少的人"。
- 必须报告的是**可观测性受限下的表现**，而不是全知条件下的表现，否则评估无意义。
- 人类步兵的走位偏好（对地图的理解、占点习惯）会被一并学入。这是接受的代价。

## 被否决的方案

- **纯模仿哨兵**：标签现成、管线现成，但上限就是各队行为树，而行为树正是要被超过的对象。
- **不做学习、只用规则写死航点**：对"守位"可行，对"根据战况换位"不可行，而后者是本项目的目标。

## 未决

若最终发现人类步兵的位置标签在哨兵上不可达（射程、底盘、场地限制），则本决策需要降级为"复现哨兵岗位"这一更小的目标，并在文档中如实记录降级原因。
