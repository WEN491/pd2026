# ADR-0001 决策承载于雷达，而非哨兵

- 状态：已接受
- 日期：2026-02（章程落笔时）

## 背景

RMUC 2026 规则手册为雷达与哨兵规定的多机通信方向是**不对称**的：

- 雷达：可以向所有己方机器人发送数据，但**只能接收哨兵机器人的数据**
- 哨兵：可以向所有己方机器人发送数据，但**只能接收雷达的数据**

即"雷达 → 全队"是单向广播，而"哨兵 → 雷达"是唯一的回向链路。这意味着**决策不可能由哨兵侧产生并交由雷达执行**——方向反了。

同时，数据集中的 `x/y/z` 是**场地全局定位真值**，不含任何感知字段。仓库现有的哨兵策略因此是在"全知观测"上训练的，而部署时必须把机载真正能感知到的东西喂进同样的槽位——这是仓库自己列出的第一号待办，从未实施。

## 决策

决策层跑在**雷达**上。雷达以全场战况为输入，输出**航点**（绝对场地坐标 + 到达半径）经多机通信下发给哨兵。哨兵的行为树承担**基线、否决、兜底**三种角色，而非被替换。

## 理由

1. **规则强制**：单向通信排除了"哨兵决策、雷达执行"的形态。
2. **观测正当性**：雷达是场上唯一一个"拥有全场视角在物理上合法"的载体。把决策放在雷达上，把仓库最大的方法论缺陷（在不可能全知的地方假设全知）变成了正当设定。
3. **算力动机**：哨兵算力有限，决策外置是原始动机。

## 后果

- 车端形成三层：**串口接收层**（收帧、校验、时间戳）→ **仲裁层**（链路健康 + 指令可执行 → 覆盖/否决/回退）→ **行为树**（基线 + 否决权 + 兜底）。
- 行为树**保留否决权与兜底**，不是"退化为运动执行器"。这是对早期表述的修正：赛场无线抖动是常态，把链路失效变成"失败"而不是"退化"是不可接受的。
- 决策频率 1 Hz 与发送频率 5 Hz **解耦**：发送只为保活与在到达后维持保持状态，不提高决策频率。
- 串口时序与状态机**不进入行为树**。心跳是链路健康，行为树管决策；把状态机塞进逐 tick 求值的节点树会制造跨节点的隐式状态。
- 行为树中"雷达分支 / 本地分支"必须是**构建期就存在的静态子树**，运行期只切换走哪一支——运行中的行为树不能安全热插拔节点。

## 未决

- 哨兵行为树的**实际接口粒度**（能否接受"航点"这一层抽象，还是只有模式级接口）。这决定车端改动量，且只有车端团队能回答。
- 哨兵在 2026 赛季新增**半自动**控制方式，与"哨兵操作手数为 0"的纯自主假设之间的关系，需要车队确认实际参赛形态。
