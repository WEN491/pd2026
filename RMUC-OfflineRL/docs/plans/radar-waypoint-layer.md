# 雷达航点层：计划与章程

> 状态：定稿待评审。**本文件不含任何代码改动。**
> 上游决策见 `docs/adr/0001`–`0004`；术语见 `GLOSSARY.md`。

## 1. 目的与范围

在雷达上训练一个决策层，以**全场战况**为输入，输出**航点**（绝对场地坐标 + 到达半径），经多机通信下发给哨兵；哨兵的行为树保留基线、否决与兜底三种角色。

**范围之外的**（明确不做，防止蔓延）：

- 目标选择与开火许可——留在行为树
- 强化姿态——日志无该字段，不做
- 雷达解析信息波、激光反制空中——射频工程，与学习无关
- 闭环仿真与在线 RL——本阶段不承诺

## 2. 为什么是这个切面

四个理由，逐条都有据：

1. **动作空间塌到 2 维（+1 个保持维）**。目标选择的软标签来自枪口朝向反演，而锥内存在多台敌方的秒占 55%，归属本身有歧义；航点不需要触碰这个问题。
2. **训练问题良定义**。航点是连续回归，而仓库所有指标中最健康的一个正是导航通道。
3. **它同时是"解决可见性 + 解决算力"的最小切片**。雷达看到全场，而"去哪"恰好是纯情报依赖的一层。
4. **它让评估也变小**。不要回答"这个策略整体好不好"（现有离线手段无法回答），只需回答"换个位置，同样的行为树输出是否变好"——可在日志上逐秒对照。

## 3. 冻结的接口

### 3.1 帧结构（草案，待官方协议附录校准）

| 字段 | 说明 |
|---|---|
| `magic` / `ver` | 帧识别与版本，防止解析旧固件的帧 |
| `seq` | 递增序号。**`seq` 变化才更新目标**，同序号仅保活 |
| `t_decision` | 决策生成时刻，用于新鲜度判断 |
| `航点 (x, y)` | **绝对场坐标** |
| `到达半径` | 离散 4 档（如 1.5 / 2.5 / 3.5 / 5 m），2–3 bit |
| `意图枚举` | 仅作日志、人读与行为树回退提示，**不承担控制** |
| `crc` | 校验 |
| （反向）哨兵位置 | 搭载在同一帧的反方向，供雷达定位哨兵 |

**没有独立的心跳字段**：持续发送本身就是心跳。

**绝对坐标而非位移**的理由：位移需要雷达知道哨兵的精确位置才能算对，而哨兵对自身位置的估计永远比雷达准。发绝对点让哨兵用**自己当前**的位置换算，少一个误差源。

### 3.2 频率与延迟预算

| 项 | 取值 | 说明 |
|---|---|---|
| 决策 | 1 Hz | 策略推理 |
| 下发发送 | 5 Hz | 保活 + 在到达后维持保持状态 |
| 上送发送 | 独立 5 Hz | 驱动被标记进度，与下发解耦 |
| 端到端延迟目标 | < 300 ms | 感知 + 推理 + 编码 + 传输 + 解码 |
| 帧新鲜度窗口 | 1.5 s | 超过即判过期 |

**推论（必须写死）**：决策是 1 Hz 而链路抖动是亚秒级，因此**策略不得依赖秒级以下的动态**。这正好与"1 Hz 战术决策"的原始建模一致；若将来提高决策频率，上送通道的进度累积与新鲜度窗口都要一起重算。

## 4. 仲裁：两个判据，四类结果

**判据 A — 传输健康**：`now − 最后一次合法帧 ≤ 400 ms` 即健康，否则链路失效。

**判据 B — 指令可执行**（链路健康时才检查）：优先目标已阵亡或位置未知、航点越界或落入界外缓冲带、航点超出可达范围、`t_decision` 过期。**任一不满足则否决整帧，不截断**（截断后可能落在更危险的位置）。

| 链路 | 指令 | 结果 | 车端动作 |
|---|---|---|---|
| 健康 | 可执行 | **覆盖** | 采纳航点 |
| 健康 | 不可执行 | **否决** | 本秒用基线，雷达下一帧正常参与 |
| 失效 | — | **回退** | 基线接管 |
| 恢复 | — | **迟滞** | 连续 3 帧合法（约 600 ms）后才允许再次覆盖 |

**到达语义**：哨兵用自身位置估计判定进入半径圆即算到达，**到达后保持**在圆内，直到 `seq` 变化。过期后"到达或超时，二者先到"——到达则保持，超时未达则交还基线。

**关键约束**：心跳与仲裁**不在行为树内**。行为树顶层是一个构建期就存在的静态分支，运行期只读一个模式标志；运行中的行为树不能安全热插拔节点。安全约束（热量、越界、弹药、单步位移）**独立于来源始终执行**，与是否覆盖无关。

## 5. 数据管线需要的改动

`rm_rl/data/features.py:build_action_raw` 目前**输出位移而非绝对坐标**：

```python
ahead = np.minimum(np.arange(T) + goal_horizon, T - 1)
vx = (x[ahead] - x)[:-1]      # 位移
```

需要新增一种动作模式输出绝对坐标。三件已就绪的事可直接复用：

1. **蓝方镜像已处理**：`_mirror_xy` 把蓝方折算到红方坐标系，标签本身已在规范坐标系下；部署时按既有做法在蓝方反镜像。
2. **非决策步已过滤**：`live = (ego.alive[:-1] > 0) & (ego.alive[1:] > 0)`，死亡秒不参与训练。
3. **合成位置必须走完整 `build_obs`**：不能只改观测里的 ego 坐标两列——队友相对位移、每个敌人的方位与距离、交战先验都依赖 ego 位置。`viz/policy_field.py:frozen_game()` 已经这样做，是现成范例。

**待解决的语义冲突**：若标签是"未来 5 秒的位置"，而哨兵提前到达并在圆内停住，标签会惩罚这个正确行为。**到达半径越大，偏差越大。** 处理方式是引入显式的"保持"维度，而不是靠降权掩盖。

## 6. 目标函数（三层）

```
J = Σ 第一层：敌方前哨站掉血与击毁（前哨站存活期间不给基地伤害计分）
  + Σ 第二层：战术核心压制（工程压制/死亡、其装配成功次数反向、英雄死亡）
  + Σ 第三层：高易伤秒数，权重 = 该单位对第二层的贡献
  + 次优先：己方情报、双倍易伤窗口的有效利用
```

惩罚只来自硬约束与机会成本。**不做负塑形**——负塑形依赖 Q 传播，而 Q 在该数据上不可信（见 ADR-0004）。

训练信号是**带权重的监督学习**：权重偏向"高进度 / 战况窗口 / 高回报"的样本。奖励权重是公开的偏好，写死在 config 并支持消融，**不声称从数据学得**。

## 7. 阶段划分

### 阶段 0 — 地基（无需数据集）

| 交付物 | 验收 |
|---|---|
| 被标记进度动力学 | **逐位复现规则示例**：5 Hz / 100% → 3.0 s 达 120；转 0% → 1 s 后 108；断 1 s → 97.6 |
| 通道抽象与帧编解码 | 无硬件下往返正确；注入丢帧/乱序/坏 CRC/半帧均被正确处理 |
| 决策层接口契约 | 与现有动作规格同构，哨兵侧不需要新的动作语义 |
| 雷达侧定位哨兵 | 回传为主、识别兜底的切换逻辑可测 |

### 阶段 1 — 确定性基线（不训练任何网络）

把航点选择写成资源分配问题——状态极小、可解。产出：

- 每局易伤秒数、双倍易伤触发次数与时机、达成阈值所需时间分布
- 人类雷达在全部可用局中的实测表现（作为对照）
- 反事实回放管线（确定性，不依赖 Q）

**同时必须报告**：613 局中真正有雷达参与的有多少局。规则明确"除雷达和飞镖系统外至少 4 台机器人"作为最低阵容，因此雷达缺席是常态而非例外，样本量可能显著小于 613。

### 阶段 2 — 特权信息蒸馏

双输入观测编码 + 带权重监督回归（含显式"保持"维）。**裁判是阶段 1 的确定性基线**：优于基线则报告增益，不优于则如实报告无增益。

### 阶段 3 — 闭环与真机

需要真机测量雷达可见集与视觉误差分布。**不在本阶段承诺范围内。**

## 10. 已知风险

| 风险 | 处理 |
|---|---|
| 有雷达的局数远少于 613 | 阶段 1 先统计并报告，据此调整结论的置信度 |
| 人类步兵的位置标签在哨兵上不可达 | 降级为"复现哨兵岗位"，并如实记录降级原因 |
| 到达半径与"未来位置"标签冲突 | 引入显式"保持"维，不靠降权掩盖 |
| 链路抖动导致在覆盖与基线间反复切换 | 迟滞 + 否决不改变链路状态；兜底迟滞参数需真机标定 |
| 把战术核心退化为固定兵种 | 词汇表已明确其为动态量；目标函数按贡献加权 |
