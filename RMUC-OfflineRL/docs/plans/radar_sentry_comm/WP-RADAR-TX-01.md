# WP-RADAR-TX-01：雷达侧收发包（v1.0-draft）

> 工作包：**WP-RADAR-TX-01**｜版本：**v1.0-draft**｜日期：2026-10-31
> 共享字节布局以 [`ICD.md`](ICD.md) 为准；本包不重复定义字段。
> 依据：2027 通信协议 V1.0.0（20261029）、2027 规则 V1.0.0（20261015）

## 1. 目标

在雷达机载计算上：

1. 解析雷达无线数据 0x0A01–0x0A05（0x0A06 密钥自用）；
2. 形成 RL 观测：4 台敌方地面 + 控制点/控制度 + 哨兵 1 Hz 团队状态；
3. 1 Hz 选动作、10 Hz 刷新目标位置，生成单条 suggestion；
4. 通过 0x0301 子内容 0x0210 发给哨兵；1 Hz 发 0x0211；收 0x0220 闭环。

**不做**：姿态/小陀螺/买弹/复活/开火命令；4 台目标完整批次下行；直接发送雷达坐标作为最终瞄准点。

## 2. 范围与职责边界

| 雷达负责 | 哨兵负责 |
|---|---|
| “去哪 / 打谁”：`action_id` + 目标 ID/位置/age/quality | “怎么打”：姿态、小陀螺、买弹、复活、何时开火 |
| 1 Hz 动作、10 Hz 目标位置 | 行为树执行、视觉/自瞄、安全回退 |

- suggestion 是**建议 + 情报**，不是控制命令；哨兵 BT 保留否决/回退。
- 目标坐标只用于接近/导航；可见时哨兵用自身视觉/自瞄。

## 5. 0x0A 输入映射

| 来源 | 内容 | 用途 |
|---|---|---|
| 0x0A01（10 Hz，cm） | 敌方重装/3/4/哨兵 x,y | 观测 + `target_x/y`（/100，转官方帧） |
| 0x0A02（10 Hz） | 敌方 1/3/4/7 血量 | 观测；`hp_valid` |
| 0x0A03（10 Hz） | 敌方允许发弹量 | 观测（可选） |
| 0x0A04（10 Hz） | 敌方金币/宏观/增益激活 | 观测（可选） |
| 0x0A05（10 Hz） | 敌方增益 | 观测（可选） |
| 0x0A06（10 Hz，6 B ASCII） | 干扰波密钥 | **雷达自用，不转发、不进观测** |

- 0x0A01 坐标单位是 **cm**；雷达内部若另有坐标系，先变换到官方帧再编码。
- 0x0A02 血量为 0 表示未上场/罚下/阵亡；`target_alive` 由血量和可见性共同判断。

## 6. Suggestion 生成规则

- **动作 1 Hz**：每 1 s 最多变一次；`action_id` 1–8，0 无效；语义由动作表维护，通信层不解释。
- **目标位置 10 Hz**：每个包刷新 `target_x/y`、`target_age_ms`、`quality`。
- **`action_seq`**：只在 `action_id` 或 `target_id` 变化时 +1；同一 seq 的 10 Hz 包不触发哨兵重入 BT。
- **无目标**：`target_valid=0`，目标字段填 0；`ENGAGE` 由哨兵回退视觉/最近可见。
- **目标失效**：`target_alive=0` / 位置失效置对应 flags；不要用死亡目标继续生成 `target_valid=1`。
- **坐标用途**：只用于接近/导航；目标可见时哨兵自瞄，不把雷达坐标当最终瞄准点。
- **时间**：`timestamp_ms` 用比赛已进行时间；`target_age_ms` 为采样到发包的年龄；禁止未来时间戳。

## 7. 0x0220 与链路

- 1 Hz 收 0x0220；解析 `last_action_seq`/`rx_count`/`crc_errors`/团队状态。
- 连续 **>2000 ms** 无 0x0220：团队状态置无效，RL 观测用掩码/上次值；不阻塞 suggestion 发送。
- 雷达侧检测 0x0220 丢失：**≤2.2 s** 报 `state lost`（阈值 2.0 s，留 200 ms 余量）。
- suggestion 发送不依赖 0x0220；即使没收到哨兵状态，也继续按安全动作发（例如 `HOLD`）。

## 8. 验收

- 0x0210 10 Hz ±1 Hz；动作字段 1 Hz 变；`action_seq` 只在动作/目标 ID 变化时 +1。
- 端到端（雷达采样→哨兵 `/radar/suggestion`）P95 < 150 ms；编码 P99 < 1 ms。
- 带宽：0x0210 360 B/s、0x0211 27 B/s；哨兵接收额度内；不排队、不重传。
- 4 个已知点目标坐标误差 <0.2 m；目标 ID 不串号；age/quality 正确；0x0A06 不转发。
- 0x0220 1 Hz 收到；ACK 反映哨兵实际应用；0x0220 丢失检测 ≤2.2 s。
- 30 min soak 无崩溃/无内存增长；suggestion 不积压；断链恢复后 2 包内继续。

## 9. 依赖与风险

| 项 | 说明 |
|---|---|
| 雷达无线接收 | 0x0A01–0x0A05 的硬件/驱动由雷达侧提供；0x0A06 自用 |
| 雷达算力 | 1 Hz 推理进程 + 看门狗；不能阻塞 0x0A 10 Hz 解析（Q6 待测） |
| 团队状态 | 依赖哨兵 1 Hz 0x0220；>2 s 超时用掩码，不猜 |
| 坐标标定 | 0x0A01 cm + 官方帧；4 点标定 <0.2 m |
| 自定义 ID | 0x0210/0x0211/0x0220 是否与雷达现有子内容 ID 冲突，需现场确认 |
| 动作表 | 8 宏语义未定；通信层只传 `action_id` |

## 10. 测试清单

1. 0x0A01 黄金帧：cm→m、ID、4 台位置；0x0A02 血量；0x0A06 不进入 suggestion。
2. 0x0210 黄金帧：逐字节；`action_seq` 动作/目标变化 +1；同 seq 位置刷新不变 seq。
3. 10 Hz 稳定性：1 s 10 包；动作 1 Hz；无积压。
4. 目标失效：无目标、死亡、位置 age>300 ms；flags 正确。
5. 0x0220：ACK 解析；2.0 s 超时；2.2 s 检测；恢复。
6. 30 min soak：无崩溃/无内存增长；带宽 < 额度。
