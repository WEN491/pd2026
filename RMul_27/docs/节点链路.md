# 节点链路（RMul_27 哨兵决策）

> 本文回答三个问题：**数据从哪来**、**BT 里谁消费它**、**动作最后发到哪**。
> 对照文件：`rm_behavior_tree/rm_behavior_tree/config/rmul_2027_sentry.xml`（主树）、
> `docs/RM2027_十二动作规划.md`（12 动作语义与规则依据）。

---

## 0. 一句话

BT 只干三件事：**选意图**（ActionSelector）、**定姿态/小陀螺**（Pub*）、**设目标点**（SendGoal）。
开火与命中判定不归 BT——自瞄和电控自己闭环。所以链路的重点是"**裁判数据能不能支撑选意图**"。

## 2. 话题 / 动作总表

方向：`←` 进 BT，`→` 出 BT。频率是协议规定值，实际以实现为准。

| 名称 | 类型 | 方向 | 生产方 | BT 侧消费者 | 频率 |
| --- | --- | --- | --- | --- | --- |
| `/game_status` | `robot_msgs/GameStatus` | ← | 裁判串口驱动 | `SubGameStatus` → `IsGameTime` | 1 Hz |
| `/robot_status` | `robot_msgs/RobotStatus` | ← | 裁判串口驱动 | `SubRobotStatus` → `IsStatusOK` | 10 Hz |
| `/robot_hp` | `robot_msgs/AllRobotHP` | ← | 裁判串口驱动 | `SubAllRobotHP` → `IsOutpostOK`/`IsEnemyOutpostOK` | 3 Hz |
| `/chassis_energy` | `robot_msgs/ChassisEnergy` | ← | 下位机 | `SubChassisEnergy` → `IsChassisEnergyOK` | 10 Hz |
| `/auto_aim_status` | `robot_msgs/AutoAimStatus` | ← | 自瞄 | `SubAutoAimStatus` → `IsAutoAimOK` | 10 Hz |
| `/auto_aim_target_pos` | `auto_aim_interfaces/Armors` | ← | 自瞄 | `SubTargetPos` → `IsDetectEnemy` / `PursueGoal` | 10 Hz |
| `/remote_status` | `robot_msgs/RemoteStatus` | ← | 遥控/裁判 | `SubRemoteStatus` → `IsRemoteStatus` | 10 Hz |
| `/decision_num` | `rm_decision_interfaces/DecisionNum` | ← | 拨杆/调试脚本 | `SubDecisionNum` → `ActionSelector` | 10 Hz |
| `terrain_zone` | `std_msgs/String` | ← | `tunnel_mode_manager`（**当前是占位，恒空串**） | `IsSemantic` | latched |
| TF `map → gimbal_yaw` | `tf2` | ← | 定位 | `GetCurrentLocation` | 50 Hz |
| `/map` | `nav_msgs/OccupancyGrid` | ← | Nav2/建图 | `MoveAround` / `PursueGoal`（贴墙检查） | latched |
| `/robot_state` | `robot_msgs/RobotState` | → | `PubRobotState` | 下位机 | 1/2/3 = 移动/防御/进攻 |
| `/chassis_mode` | `robot_msgs/ChassisMode` | → | `PubChassisMode` | 下位机 | 0 正常 / 1 加速旋转 / 2 过起伏 / 3·4 过盲道 |
| `/robot_control` | `rm_decision_interfaces/RobotControl` | → | `RobotControl` | 下位机 | `stop_gimbal_scan` + `chassis_spin_vel` |
| `/auto_aim_mode` | `robot_msgs/AutoAimMode` | → | `PubAutoAimMode` | 自瞄 | 0 敌 / 1 小符 / 2 大符 / **3 前哨** |
| `/enemy_status` | `sp_msgs/EnemyStatusMsg` | → | `PubEnemyStatus` | 自瞄 | 无敌目标黑名单 |
| `/autoaim_target` | `sp_msgs/AutoaimTargetMsg` | → | `PubAutoaimTarget` | 自瞄 | 锁定目标白名单 |
| `/super_capacitor` | `robot_msgs/SuperCapacitor` | → | `PubSuperCapacitor` | 下位机 | 0 关 / 1 开 |
| `navigate_to_pose`（action） | `nav2_msgs/NavigateToPose` | → | `SendGoal` | Nav2 | 目标 `"x;y;z;qx;qy;qz;qw"`（map 帧） |

> ⚠ 两个端口坑（改树前必看）：
> - `PubAutoAimMode` 只认 `auto_aim_mode`；写 `key_name` 是死代码（默认值 0 永远先命中）。
> - `RobotControl` 没有 `topic_name` 端口，话题由 `default_port_value` 固定为 `robot_control`。

## 3. 一次 tick 发生了什么

主程序是 `spin_some(5 ms) → tickOnce() → sleep(10 ms)` 的循环（**不是** `tickWhileRunning`，否则裸订阅收不到数据）。

```
tick #n
 ├─ ReactiveSequence 从上往下
 │   ├─ SubGameStatus / SubRobotStatus / SubAllRobotHP   （有新消息才写黑板，无消息也算 SUCCESS）
 │   ├─ ForceSuccess(SubTargetPos)   ForceSuccess(GetCurrentLocation)   （TF/自瞄没就绪也不挡树）
 │   ├─ IsGameTime(4, 0..420)        ← 不在比赛中就整树不推进（仿真要 --mock-referee）
 │   ├─ SetBlackboard ×8             ← 点位表，每个 tick 重写（幂等）
 │   └─ Fallback
 │       ├─ Sequence
 │       │   ├─ SubDecisionNum       ← 拨杆动作号
 │       │   └─ ActionSelector
 │       │       └─ children[action-1]->executeTick()
 │       │           ├─ RUNNING → 原样返回
 │       │           ├─ SUCCESS → 保持 RUNNING，cooldown_ms 后再重入
 │       │           └─ FAILURE → FAILURE（落到下面的本地安全策略）
 │       └─ SubTree TeamHold        ← 没有动作号 / 动作号越界 / 子树失败时的兜底
```

`ActionSelector` 的三条约定（写在 `plugins/control/action_selector.cpp` 头注释里）：

1. **动作号变了才切子树**：`haltChild(旧)` → 进新子树，导航目标等 RUNNING 状态被清理；
2. **子树 SUCCESS ≠ 宏结束**：保持 RUNNING，`cooldown_ms`（默认 1000）后重入，避免 10 ms 级重复下发；
3. **子树 FAILURE 直接透传**：由 `Fallback` 兜底，不缓存失败，下个 tick 可重试。

## 4. 12 个动作的链路

"判断节点"一列里带 `[待接]` 的，就是 P0 之后要补的节点；现在用近似条件顶替。

| # | 动作 | 需要的输入 | 判断节点 | 执行节点 | 目标点 | 成功/反馈 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 协同进攻 | `/auto_aim_target_pos`、TF、`/robot_hp` | `IsDetectEnemy(12 m)` | `PursueGoal`→`SendGoal`，无敌人则 `SetBlackboard`→集结点 | 对方中央高地 / 追击点 | 到点被 `SendGoal` 判 SUCCESS |
| 2 | 协同防守 | — | 无（默认） | 姿态防御 + 小陀螺 + `SendGoal` | `goal_home_guard` | 同上 |
| 3 | 打己方方位前哨 | `/robot_hp`（`outpost_hp`）；`[待接]` `0x0101` 阵地控制 | `IsOutpostOK(>0)`；`[待接]` `IsOutpostStatus(own, temp/none)` | `PubAutoAimMode(3)` + `SendGoal` | `goal_home_outpost` | `[待接]` 前哨血量归零 / 控制权翻转 |
| 4 | 打对方方位前哨 | `/robot_hp`（`enemy_outpost_hp`） | `IsEnemyOutpostOK(>0)` | 同上 | `goal_away_outpost` | `[待接]` 对方前哨血量归零 |
| 5 | 抢占堡垒 | `/robot_hp`；`[待接]` `0x0101` 堡垒位 + `stage_remain_time` | `IsOutpostOK` 二选一；`[待接]` `IsFortressUsable(side)` | 姿态防御 + `SendGoal` + 站卡不动 | `goal_home/away_fortress` | `[待接]` 堡垒位=己方激活 / 累计 10 s |
| 6 | 驻守己方方位前哨站 | `/robot_hp`；`[待接]` `0x0101` 控制状态 + `0x0204` 回血 buff | `[待接]` `IsOutpostStatus(own, full)` | 姿态防御 + 小陀螺 + `SendGoal` | `goal_home_outpost` | `[待接]` 回血 buff > 0 |
| 7 | 驻守对方方位前哨站 | 同上 | `IsEnemyOutpostOK` + `[待接]` `IsOutpostStatus(enemy, full/temp)` | 同上 | `goal_away_outpost` | 同上 |
| 8 | 原地死战 | — | 无 | 姿态防御 + `RobotControl(3.0)`（**不发导航**） | 当前位置 | 无终点（超时由上层/雷达切动作） |
| 9 | 追击某个机器 | `/auto_aim_target_pos`、TF；`[待接]` `0x0210` 目标 | `IsDetectEnemy(12 m)`；`[待接]` `RadarTargetPose`（age 门限） | `PursueGoal`→`SendGoal` | 追击点 3 m | 目标消失 → FAILURE → 截图兜底 |
| 10 | 回基地回血 | HP（`/robot_status`）；`[待接]` `0x0101` 补给区位 | `IsStatusOK(hp)`；`[待接]` `IsGainPointActive(supply)` | 移动姿态赶路 → 到位切防御 → 等 | `goal_supply` | `[待接]` HP/弹药达标 |
| 11 | 回己方方位前哨回血 | `/robot_hp`；`[待接]` `0x0101` 控制状态 | `IsOutpostOK`；`[待接]` `IsOutpostStatus(own, full)` | 同 10 | `goal_home_outpost` | `[待接]` `IsHealing` |
| 12 | 回对方方位回血 | 同上 | `IsEnemyOutpostOK` + `[待接]` `IsOutpostStatus(enemy, full/temp)` | 同 10 | `goal_away_outpost` | 同上 |

`goal_*` 全部在 `MainTree` 顶部用 `SetBlackboard` 写入（map 居中系，见规划文档附录 A），
12 个分支**内联在同一个黑板里**（原因见下）。

> ⚠ **为什么主树故意不用 `<SubTree>`**
> BT.CPP v4 的 `SubTreeNode` 会给子树创建**独立黑板**（`decorators/subtree_node.h` 头注释写明
> "creating a separated BlackBoard"），而 `_autoremap` 也只能搬构造期就存在的条目。本工程所有
> 数据都是运行期由 `Sub*` 节点写进黑板的（`{robot_hp}` / `{armors}` / `{current_location}`），
> 用 `<SubTree>` 会在第一次 tick 抛
> `error reading port [goal_pose]: getInput() failed because it was unable to find the key ... remapped to ...`
> 并直接 `terminate`。所以 12 个分支全部内联；要拆成子树，必须给每个 `<SubTree>` 传端口字面量
> （例如 `goal_pose="-3.02; 3.90; 0.0; 0; 0; 0; 1"`），不能依赖父树黑板里的 `{...}`。

## 5. 还缺的节点，插在哪

| 节点 | 类型 | 插入位置 | 数据源 |
| --- | --- | --- | --- |
| `SubEventData` / `EventData.msg` | sub + msg | MainTree 数据面（`SubAllRobotHP` 之后） | `0x0101` |
| `IsOutpostStatus(side, state)` | 条件 | 动作 3/6/7/11/12 的子树首节点 | `EventData` + `team_color` |
| `IsFortressUsable(side)` / `IsFortressActive(side)` | 条件 | 动作 5 的 `WhileDoElse` 判据 | `EventData` |
| `IsGainPointActive(point)` | 条件 | 动作 5/6/7/10/11/12 的"到位判定" | `EventData` |
| `SubBuff` / `Buff.msg` | sub + msg | 数据面 | `0x0204` |
| `IsHealing(min_pct)` | 条件 | 回血类子树 | `Buff.recovery` |
| `SubProjectileAllowance` / `msg` | sub + msg | 数据面 | `0x0208` |
| `IsAmmoBelow` / `IsGoldAtLeast` | 条件 | `EnsureSurvivability`、动作 1/7 | `0x0208` |
| `SubSentryInfo` / `msg` | sub + msg | 数据面 | `0x020D` |
| `IsOutOfCombat` | 条件 | `EnsureSurvivability`（远程回血前置） | `0x020D.bit0` |
| `SentryPosture`（1–6） | 发布 | 替换全部 `PubRobotState` | `0x0120` |
| `SearchOnCard(radius, point)` | 动作 | 所有"驻守/回血"的到位段（`SendGoal` 之后） | `MoveAround` + `IsGainPointActive` |
| `RadarTargetPose` | 动作 | 动作 9 的 `PursueGoal` 之前 | `0x0210` + `T_map_field` |
| `SubRadarSuggestion` + `radar_decision_adapter` | sub + 适配 | `ActionSelector` 之前（写 `action_id`） | `0x0301` 子内容 `0x0210` |
| `EnsureSurvivability` | 动作（恒 SUCCESS） | MainTree 守卫之后、`Fallback` 之前 | `Buff`/`ProjectileAllowance`/`SentryInfo` |

接到位后的等价改动：**子树结构不动**，只把判断节点换掉、`PubRobotState` 换成 `SentryPosture`、
`SendGoal` 后面补 `SearchOnCard`。

## 6. 启动顺序（谁先谁后）

1. **裁判串口驱动**（或 `./run_bt_nav.sh --mock-referee` 造假数据）
   —— 没有 `/game_status`，`IsGameTime` 恒假，整棵树停在第一个守卫上。
2. **定位 + Nav2**（`beijixiong`）—— 提供 TF、`/map`、`navigate_to_pose` 动作服务器。
3. **自瞄** —— 提供 `/auto_aim_target_pos`；没有它只是打不准，树照样跑。
4. **行为树**
   ```bash
   source install/setup.bash
   ros2 run rm_behavior_tree rm_behavior_tree --ros-args \
     -p bt_xml:=$PWD/rm_behavior_tree/rm_behavior_tree/config/rmul_2027_sentry.xml \
     -p use_sim_time:=false
   ```
5. **Groot2** 连 `1667` 端口看实时节点状态。

> 行为树跑在根命名空间、导航挂在 `/<ns>` 下时，必须用 `-r __ns:=/<ns>`（**不能**用 remap 动作名，
> ROS2 的 action 底层实体是 `/<name>/_action/*`，只 remap 基名不生效）。`run_bt_nav.sh` 已经处理。

## 7. 自检命令

```bash
ros2 node list                                   # 行为树 + nav2 + 驱动
ros2 topic hz /game_status                       # 应 ≈1 Hz（没有 → 树停在 IsGameTime）
ros2 topic echo /robot_hp --once                 # 前哨/基地血量从这来
ros2 topic echo /decision_num --once             # 拨杆动作号 1..12
ros2 action list | grep navigate_to_pose         # 没有 → SendGoal 必定超时/失败
ros2 run tf2_ros tf2_echo map gimbal_yaw         # GetCurrentLocation 用的变换
ros2 topic echo /robot_state                     # 姿态是否按子树在切
```

动作号 1..12 与子树的对应关系见 `ActionSelector` 的子节点顺序（= 12 动作规划里的编号）。
